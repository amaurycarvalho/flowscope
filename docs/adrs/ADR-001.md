# ADR-001: Arquitetura e Decisões Técnicas do FlowScope

## Status

Aceito

## Contexto

O FlowScope precisa processar dados públicos de negociação da B3, calcular dezenas de indicadores de fluxo de ordens com dependências entre si, e apresentá-los em uma interface gráfica desktop. A ferramenta deve ser distribuível como binário único e funcionar offline via cache.

## Decisões

### 1. Clean Architecture (Arquitetura Limpa) com DDD

**Decisão:** Organizar o código em 4 camadas — `domain/`, `application/`, `infrastructure/`, `presentation/`.

**Consequências:** Domínio isolado de frameworks e infraestrutura. Use cases orquestram a lógica de aplicação. A camada de infraestrutura implementa portas definidas na aplicação (ex.: `DataRepository` protocol). Testes do domínio não dependem de rede ou banco de dados.

### 2. DAG Engine para Indicadores

**Decisão:** Implementar um motor de execução que resolve dependências entre indicadores via ordenação topológica (DAG). Cada indicador é uma `IndicatorStrategy` com `id` e `dependencies`.

**Consequências:** Indicadores são registrados e executados na ordem correta automaticamente. Adicionar um novo indicador requer apenas criar a strategy e registrá-la no engine. Não há execução redundante.

### 3. Strategy Pattern por Indicador

**Decisão:** Cada indicador (VWAP, CLV, Daily Efficiency, etc.) é uma classe que implementa `IndicatorStrategy`.

**Consequências:** Indicadores são testáveis isoladamente. Novos indicadores não alteram código existente (aberto para extensão, fechado para modificação). Hoje são 22 strategies registradas.

### 4. GUI com Python Tkinter

**Decisão:** Usar tkinter (biblioteca nativa do Python) para a interface gráfica.

**Consequências:** Sem dependências externas pesadas para a GUI. Binário final mais enxuto. Limitações estéticas inerentes ao tkinter, mas adequadas para ferramenta analítica desktop. Suporte nativo multiplataforma.

### 5. Matplotlib para Visualização

**Decisão:** Usar matplotlib para todos os gráficos e painéis.

**Consequências:** Integração direta com tkinter via `FigureCanvasTkAgg`. Suporte a exportação de gráficos como imagem. Curva de aprendizado já estabelecida na comunidade Python.

### 6. Arquivos CSV da B3 como Única Fonte de Dados

**Decisão:** Consumir o arquivo `TradeInformationConsolidated` disponível publicamente no site da B3, sem API paga ou cadastro.

**Consequências:** Gratuito e sem barreiras de acesso. Dependência da disponibilidade e formato do arquivo da B3. Cache local por data para evitar downloads repetidos.

### 7. Cache em Arquivos JSON

**Decisão:** Cache local em `~/.flowscope/cache/` usando arquivos JSON com TTL configurável.

**Consequências:** Opera offline com dados em cache. Cache de portfólios (IBOV, IDIV, IFIX) com TTL de 7 dias. Estrutura simples sem banco de dados.

### 8. PyInstaller para Distribuição

**Decisão:** Gerar binário único por plataforma via PyInstaller (configuração em `flowscope.spec`).

**Consequências:** Usuário final não precisa instalar Python ou dependências. Binário maior (~30-50MB) mas plug-and-play. Suporte a Linux, Windows e macOS.

### 9. Sampling Strategies

**Decisão:** Oferecer métodos de amostragem de datas (Fibonacci, Monte Carlo, etc.) para análise histórica.

**Consequências:** Permite análise de períodos longos (60-90 dias) sem baixar todos os dias úteis. Reduz tempo de carga e volume de dados.

### 10. MVPVI (Model-View-Presenter-View Interface)

**Decisão:** Separar a lógica de apresentação em `Presenter` e `Controller`, com a GUI implementando um protocolo `GUIView`.

**Consequências:** Controller orquestra ações do usuário. Presenter formata dados para a view. View (tkinter `app.py`) é passiva. Facilita testes da lógica de apresentação sem instanciar tkinter.

## Equivalências

| Conceito | Implementação |
|---|---|
| View | `FlowScopeGUI` (`app.py`) + protocolo `GUIView` |
| Presenter | `FlowScopePresenter` (`presenter.py`) |
| Controller | `FlowScopeController` (`controller.py`) |
| Use Cases | `AnalyzeTickersUseCase`, `ExportVWAPUseCase`, `LoadIndexPortfolioUseCase` |
| Ports | `DataRepository` protocol, `LogPort` protocol |
| Adapters | `B3DataRepository`, `PythonLogAdapter` |
| Domain Strategies | 22 classes em `domain/strategies/` |
| DAG Engine | `IndicatorEngine` resolvendo dependências via topological sort |
| Value Objects | `Price`, `Volume`, `Ticker`, `Delta` |
